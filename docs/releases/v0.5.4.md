## 安装

从本页 Assets 下载 `luyi0825-zcode-acp-0.5.4.tgz`，本地安装：

```bash
npm install -g ./luyi0825-zcode-acp-0.5.4.tgz
zcode-acp login      # 浏览器授权登录（一次性）
zcode-acp doctor     # 自检：Node / CLI 定位 / 登录态 / 模型列表
zcode-acp setup      # 自检 + 打印各客户端接入配置
```

`doctor --probe` 会实跑一轮 headless 对话做端到端验证。详细步骤见 [docs/usage-guide.md](https://github.com/luyi0825/zcode-acp/blob/main/docs/usage-guide.md)。

## 修复

### Claude stream-json 入口的长任务被误判为无响应

此前该入口整轮只在结束时回一条完整回复，中间十到几十分钟完全静默。宿主侧按「距上次语义事件」判活（实测预算 10 分钟），于是读大仓库、批量改代码这类长任务会在跑到一半时被当成卡死终止，报 `provider_zero_events`。

现在把执行过程实时翻译成语义消息：

- `tool.updated` 的 `scheduled` → `assistant` 消息里的 `tool_use` 块（带 `id` / `name` / `input`）；
- `tool.updated` 的 `result` → `user` 消息里的 `tool_result` 块，`is_error` 取 `success === false`；
- 工具输出按 20 KB 截断，避免 Bash 的大段输出撑爆消息体；
- 文本增量在工具边界与回合结束时成段发出，不逐字碎片化；
- 新增 60 秒保活：纯文本长任务即使没有工具事件，也会定期把已累积文本作为一段发出。

收尾时只有本轮完全没有增量事件（老版本 CLI 或纯错误）才回退成整段兜底，正常路径不会重复。

### 宿主的 token 统计恒为 0

此前该入口只在末尾 `result` 行带 usage，且字段口径与宿主不一致，宿主侧统计到的输入 / 输出 / 缓存 token 四项长期为 0。

- **用量按请求累加**：逐条取 `session.updated` 的 `payload.usage` 累加，`inputTokens` 是单次请求的完整输入，多次请求各自计费；
- **口径对齐**：zcode 的 `inputTokens` 含缓存命中，Claude 的 `input_tokens` 不含，扣减后上报；`reasoning` 是 `output` 的子集，不单列以免重复计费；
- **usage 挂到 assistant 消息**：宿主按消息 id 逐条聚合 token，只在末尾 `result` 挂用量拿不到任何一条，现在每条 `assistant` 消息带该轮累计用量（与 Claude Code 行为一致），工具结果不挂；
- **补 `modelUsage`**：`result` 行增加「模型名 → 驼峰字段用量」，供宿主按模型落库。

无 usage、解析失败或值非法时返回 null，不阻断执行。
