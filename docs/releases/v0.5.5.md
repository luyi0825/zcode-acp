## 安装

从本页 Assets 下载 `luyi0825-zcode-acp-0.5.5.tgz`，本地安装：

```bash
npm install -g ./luyi0825-zcode-acp-0.5.5.tgz
zcode-acp login      # 浏览器授权登录（一次性）
zcode-acp doctor     # 自检：Node / CLI 定位 / 登录态 / 模型列表
zcode-acp setup      # 自检 + 打印各客户端接入配置
```

`doctor --probe` 会实跑一轮 headless 对话做端到端验证。详细步骤见 [docs/usage-guide.md](https://github.com/luyi0825/zcode-acp/blob/main/docs/usage-guide.md)。

## 重点：装完基本不用配任何参数

这一版把「本机布局」全部改成自动发现，之前需要手工拼 `~/.zcode-acp.env` 的四个变量现在都能推出来：

| 原需手工配置 | 现在的来源 |
| --- | --- |
| `ZCODE_HOME` / `ZCODE_WINDOWS_APP_INSTALL_DIR` | Windows 读注册表卸载表里的 `InstallLocation`，再回退标准安装目录 |
| `ZCODE_DATA_BASE_DIR` | 读 `~/.zcode/v2/setting.json` 的 `dataBaseDir`（Desktop 重定向数据目录时持久化的值） |
| `ZCODE_PERSONAL_PROVIDER_CONFIG_FILE` | 由数据目录拼 `.zcode/v2/provider_config.json` |
| `ZCODE_BUILTIN_PROVIDER_CONFIG_FILE` | 由 CLI 安装根拼 `resources/config/provider/zcode-builtin.json` |

在**完全没有任何 `ZCODE_*` 变量、也没有 `.zcode-acp.env`** 的干净终端里实测，`doctor` 四项全过、退出码 0。

`~/.zcode-acp.env` 仍然支持，但只作为**覆盖**用。只有在绿色版/解压版（注册表里没有卸载记录）、换了机器只拷了数据目录、或一份数据目录要跑多个 profile 时才需要写。

## 修复

### 内置 provider 配置在 Windows 下永远定位不到

`applyZcodeRuntimeEnv` 从 CLI 路径向上两级推导安装根，但 Windows 的 CLI 在 `<安装根>/resources/glm/`，少算一层 `resources`，拼出来的 `zcode-builtin.json` 路径必然不存在。

后果是 `models.js` 拿不到内置规则：`disabled` 的模型不会被过滤（实测从 11 个变成 14 个），思考档位退化成旧版三档 `low/high/max`。

现在抽出 `builtinProviderConfigAt()`，同时尝试 `resources` 目录及其父目录，两种布局都覆盖，`zcode.js` 与 `models.js` 共用同一份定位逻辑，不会再分叉。

### 非 Desktop 终端读到旧配置，报 provider 401

Desktop 重定向数据目录后，zcode CLI **只认 `ZCODE_DATA_BASE_DIR` 环境变量，不读 `setting.json`**。桥接进程拿不到这个值就退回家目录，读到 `~/.zcode` 下的旧 provider 配置，表现为 `API Key 不存在`，而用户完全无从判断原因。

现在 `dataBaseDir()` 会在环境变量缺失时自动读 `setting.json` 的 `dataBaseDir`，并在注入子进程前完成校验：只接受绝对路径、拒绝含 `..` 的路径、目录必须真实存在，任一项不满足就当作没有重定向。

### `doctor` 的登录态会误报

第 3 项检查固定读 `ZCODE_DATA_BASE_DIR`，缺失时退回家目录，可能读到一份几个月前的旧凭据，显示 `[ok] 已登录` 而实际生效的是另一份。现在统一走 `dataBaseDir()`，与第 4 项的模型列表口径一致；模型列表读不到时还会打出实际尝试的配置路径。

### `doctor --probe` 的报错基本不可读

provider 报错时 stderr 会混入崩溃中途的压缩 bundle 源码与栈帧，原实现只按「行长度 ≤ 300」过滤，结果把源码片段当有效信息输出，真正的原因 `providerMessage: 'API Key 不存在'` 反而被尾部截断挤掉。

现在按「很长的行 + 几乎没有空白」判定压缩源码（正常错误消息总有断词的空格），丢弃栈帧，并把 `providerXxx:` 这类结构化字段前置。

### 同会话并发 prompt 会串话

串行保护原本检查 `record.stop`，而它要等 `runTurn` 的 `onStart` 才赋值，中间隔着一个 `await knownNames()`。首次命令发现实测耗时 1.7 秒，这段时间内连发两条 prompt 会**都通过检查**，各自 spawn 一个 zcode 进程，最后一个覆盖 `record.zcodeSessionId`，上下文就串了。

现在在进入 prompt 时同步置 `record.busy` 占位，外层 `try/finally` 保证所有返回路径都释放。冒烟测试新增了这条用例——必须放在进程的**首次** prompt 上才测得出来，缓存建立后撞不到那个窗口。

### MiCO 任务模板占满会话标题与首条消息

MiCO 用固定模板包裹每条消息（`## Task Initiator` 发起人与产物目录 → `[user message=<id> version=<n>]` → 用户原话 → `## Human interaction` 规则）。zcode CLI 取首条输入的**原文**当会话标题，于是 ZCode 项目列表显示的是 "## Task Initiator This task was initiated by **XXX** ..."，首条消息也被模板占满，用户原话淹在中间。

现在新增 `splitTaskEnvelope()` 把模板拆出去：用户原话作为 prompt 正文（标题就取它），模板原文原样写入本轮临时附件，经 `--attach` 交给 CLI——实测附件内容进模型上下文并跨 `--resume` 保留，但不出现在标题与首条消息里，信息量一字不减。任何一段对不上模板形态（缺标记、纯模板消息）时整体原样下发，宁可显示难看也不吞用户输入。

同时把技能改写挪到拆解之后：`/技能名` 原本被模板裹住永远命不中首行，拆开后用户的斜杠命令回到首行，改写才生效。

### 内置命令进不了客户端的斜杠菜单

`commands list --json` 只返回用户自定义命令，内置命令在 CLI 里是硬编码的、没有导出接口，因此 `/compact`、`/goal` 在 headless 下明明能执行，客户端菜单里却看不到、点不到。

现在在 `commands.js` 声明 `BUILTIN_COMMANDS` 并排在自定义命令之前，`slash-text.js` 另有一份 `NATIVE_COMMANDS` 兜底保证它们永不改写成 `/skill`（否则命令失效）。只收录实测在 `-p` 模式下真正执行的两条：其余内置命令（`/model` `/mode` `/mcp` `/plugins` `/effort` `/dwf` `/locale`）headless 下不被识别、会被当成普通提示词，`/workflow` `/fork` 直接退出码 1；模型、模式、思考级别已由 ACP 的 `set_model` / `set_mode` / `set_config_option` 承担。

### 其他

- `normalizeCwd` 补 `try/catch`：客户端给不可读路径时 `statSync` 抛异常会冒泡成协议错误，现在回退主目录；
- 会话记录加上限（64 条），超限淘汰最旧的**空闲**记录，避免宿主长期复用进程时无限增长；运行中的轮次不淘汰；
- 注册表查询改为延迟执行 + 进程级缓存：标准安装路径命中时完全不查注册表，避免每次解析都付几十毫秒的同步开销；
- `claude.js` 的兜底模型不再借用 `claude-sonnet-4-6` 这个无关的真实模型名，改为中性的 `zcode` 占位且不声明思考档位，避免宿主把它当真实模型展示或按模型落库；
- `doctor` 在 Windows 上只认 `APPDATA`，POSIX 走 `XDG_CONFIG_HOME ?? HOME`；
- 报错上下文补 `USERPROFILE` 回退，Windows 上不再显示 `HOME=(unset)`。

### Claude stream-json 入口

- 内置斜杠命令（`/compact`、`/goal`）的回复不产生流式增量，此前客户端什么都看不到，现在在轮次结束时补发；
- `parseCommandOutput` 不再取命令输出里的 `sessionId`——实测那是命令执行时的临时会话，拿它 `--resume` 会报 `Session not found`，续接必须沿用原会话。

### Claude 入口上报的 token 用量恒定翻倍

实测 zcode 每次模型请求结束发**成对**的 `session.updated`：一条仅含 usage，一条是带 usage + contextWindow + content 的轮末汇总，载荷相同。旧实现两条都计入，每次请求的用量记了两遍；此外整轮**累计值**挂到每一条 assistant 消息上，而宿主（MiCO Claude 适配器）按消息 id 逐条建账后**跨消息求和**，多工具轮里同一请求的量被反复叠加。真实一轮（2 次请求）实测上报恰好是真实消耗的 2 倍。

- 只认带 `contextWindow` 的轮末事件（与 ACP 路径同一判别），每次请求只计一次；
- 改为「每请求一份、挂过即清」的账本：该次请求的用量挂到**下一条** assistant 消息（请求间无 assistant 消息时继续攒），宿主按消息求和后正好等于各请求之和；整轮累计只保留在末尾 `result` 行；
- 保活 flush 把最后一段文本提前发完时，补一条空 content 的 assistant 消息挂载剩余用量，避免漏计（宿主对该形态同样建账）。

## 安全

- 路径进文件读取前统一校验：绝对路径、拒绝 `..`、必须是普通文件。`models.js` 抽出 `configPath()` 并把校验提到调用点，不再依赖下游函数隐式防护；
- **客户端注册的配置根同样按不可信输入校验**：`APPDATA` / `XDG_CONFIG_HOME` / `HOME` 是环境变量，此前 `safeJoin` 只保证「不逃出父目录」，受污染的父目录（含 `..` 或相对路径）仍能把探测与写入引到任意位置；现在入口处先要求绝对路径且路径段不含 `..`，不合格直接跳过注册；
- `setting.json`、`ZCODE_PERSONAL_PROVIDER_CONFIG_FILE`、`ZCODE_BUILTIN_PROVIDER_CONFIG_FILE` 均按不可信输入处理，非法形态一律忽略并回退；
- **用户输入无法逃逸成命令行选项**：`buildArgs` 里所有可变值（`--prompt=`、`--cwd=`、`--resume=`、`--attach=`）统一改成等号绑定，配合 spawn 数组传参，即使值以 `-` 开头也只能作为该选项的值被消费；`runTurn` 入口显式拒绝非字符串 `text`；
- **结束子进程不再经命令行解释器**：`killTree` 原用 `execFile("taskkill", [...])`，改为 `spawn` + 数组参数，pid 先限定为正安全整数并断言十进制形态，taskkill 不存在或进程已退出时静默忽略。
